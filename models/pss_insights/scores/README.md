# PSS learner scores, attempts and Quiz items

The score models join the registered learner in the exact CCX to the applicable logical master subsection. For an instructor-facing query, apply the class context’s authorized institution and CCX pairs **before aggregation**. Instructor assignments establish access. They never participate in the fact join. Operators use the restricted schema to investigate unmapped launches, identities, grade events and question results. [Class and roster](../context/README.md) · [Published inventory](../core/README.md)

## Reporting contracts

| Relation | Grain, units and keys | Interpretation |
| --- | --- | --- |
| `rpt_pss_activity_scores_current` | One row per `(ccx_id, actor_id, subsection_block_id)` with grade or sitting evidence. `score_pct` is nullable Float64 on 0–100. | Current snapshot for published, applicable activities. Keep the selected source IDs, observation time, rule and status alongside a displayed score. An activity with no evidence can have no row. |
| `rpt_pss_activity_attempts` | One linked MeasureUp source sitting per registered actor, class and logical subsection. `attempt_key` namespaces the original `exam_attempt_id`. The test FK is `exam_test_id`. Both source identifiers are strings. | Carries raw and normalized score/mode/state, UTC start/finish, ordinal, eligibility, provider pass flag and version evidence. A valid zero counts. Missing score can coexist with qualifying participation. |
| `rpt_pss_quiz_item_results` | One row per verified Quiz `attempt_key` and provider `item_key`. The original provider attempt and question IDs are retained. | Current surviving source results, attributable to the dated parent sitting. A missing/ambiguous score has a reason. A provider's raw Decimal score has no exported points denominator or guaranteed item percentage. `item_answered_at`, `earned_points` and `possible_points` are nullable. |
| `int_pss_activity_attempt_coverage` | One continuous verified UTC interval per currently applicable CCX/subsection/publication. | Independent evidence can certify a finite reporting period. No deployed feed in this contract certifies all-time final-attempt completeness. |

**Whole-activity evidence.** Course Licensing supplies the scoped enrollment and xAPI actor. The LTI launch must match the class and a single parent subsection in the exported course trees. A moved component, ambiguous parent, unmatched actor, contradictory product, or launch without a persisted attempt has an explicit diagnostic. The structure export has a dump timestamp and individual block edit times. A dated sitting requires its LTI block in the last received master dump at or before its start. A later dump that omits the block withholds linkage until it reappears. Competing dump IDs or inconsistent clocks leave that observation unresolved. Individual edits cannot backdate the parent relationship. A publish or dump that produced no rows at all requires independent reconciliation. The stored class and logical key can be reconciled through `int_pss_measureup_attempt_diagnostics`. The registrar, instructor and taxonomy joins never multiply attempt rows.

**Publication at the time of evidence.** Each observed publication ends the previous one, even if the next publication is unmapped, empty or conflicting. Each CCX needs evidence of applicability in that revision. The attempt keeps its original class/actor/key when earlier Studio history cannot establish a type. Its historical type and affected eligibility stay unknown. A Quiz that later becomes a Final Exam keeps its Quiz classification at the earlier start. The observed attempt revision and current/last class catalog revision are separate columns. Missing publication changes and historical mapping approvals cannot be reconstructed from the initial backfill.

**Current scores (decision pending).** The LMS subsection's `earned` event carries weighted totals calculated by Open edX. For a valid observation, `100 * raw / max` preserves partial credit and must agree with the separate scaled field. For example, one point from two possible plus zero from eight gives a total of 1/10, or 10%. A missing score field, zero denominator or inconsistent scaled value stays unavailable. This calculation does not require inferring which unobserved problems the learner attempted. Replays of one immutable LMS statement collapse. Its own timestamp is preferred, with the earliest observed emission used when the statement omits a timestamp. A contradictory UUID is diagnostic. Current score selection excludes grades or sittings that belonged to a different activity type.

Without a per-run override, a current score requires the available candidates to agree and be valid. Differing retakes, an unfinished candidate under the agreement rule, and conflicting sources leave a reason. Content/Product can set `pss_current_score_rules` by exact master-course key and activity type to `lms_subsection` or `measureup_latest_finished`. The latter selects the last source finish time. Distinct tied observations with conflicting scores still require adjudication. Current or historical LMS course grades are separate metrics.

**Eligibility and version (decision pending).** Load the reviewed `pss_measureup_attempt_rules` seed with one row per master, activity type, normalized flow state and mode. Its three 0/1 outputs distinguish participation, eligible Practice Exam and qualifying Final Exam. For an applicable purpose, a missing or invalid rule yields NULL. Product/provider owners must approve the state and mode combinations, including unfinished attempts. One final learner can have several distinct qualifying sittings. Calculate learner-level pass outcomes in class reporting.

`pss_measureup_score_units` separately specifies `percent` or `fraction` per master and whether the provider has verified the response's test-version pairing for that run. The provider's reporting API retrieves the latest state for a user and product together with a response-level test structure. The Ulmo importer attaches the latest matching launch and persists the test FK. The LMS enforces uniqueness on the test and launch pair. A second provider sitting that the importer never persisted has no row in ClickHouse. Positive scores need an approved unit. The model exposes the raw pass flag, catalog mark and applicable `cut_score` separately. Historical `cut_score` requires evidence that the returned test version applies to the selected state, an exact catalog FK, a consistent mark within the observed version history and a version timestamp at or before the start. Before enabling version pairing, obtain a provider guarantee that covers retakes and historical replays for the specified run. Preserve unknown thresholds and conflicting pass evidence for adjudication.

**Ordinals, items and time (decision pending).** The `provider_attempt_number` comes from the existing MeasureUp learner/class/test/mode sequence. The PSS `attempt_number` additionally partitions by logical activity and filters on approved eligibility. Numeric source IDs break ties between simultaneous starts. Display filters apply **after** numbering. Corrected or tombstoned sources can change historical results and ordinals on the next refresh. An observed provider result PK identifies a correction or replay of that result. Multiple surviving result PKs for the same question and attempt yield one disputed item with `within_attempt_selection_unapproved`. Known contradictions between question-catalog ancestry and sitting ancestry are quarantined. An absent item dictionary can preserve an independently linked question result and score while its objective IDs remain unknown. Keep untagged items and aggregate at the original item or attempt grain before joining taxonomy assignments.

Native problem events provide available points, outcomes and per-problem ordinals in restricted `int_pss_native_item_evidence`. A native subsection grade, a problem submission, and a Skillable launch provide different evidence. None supplies a verified whole-Quiz or whole-Lab sitting ID in these exports. Native problem events therefore retain their linkage gap. A Lab can have an LMS subsection score without a supported Lab attempt. For MeasureUp, source-update and dump times are available even when the item-answer time is unknown. Product and data owners still need to confirm the reporting week, the intended event time and the policy for repeated item results.

## Periods and zero attempts

Supply the macro `pss_activity_attempt_counts(start, end)` with two UTC SQL timestamp expressions. It returns the **observed** dated participation and a separate nullable **verified** participation count for each current class activity. The interval includes the start and excludes the end. A sitting whose participation or start time cannot be decided can make the period unresolved. This query uses the current eligible roster and applicable inventory. Changes to either can affect historical results.

An independent operations model can supply `pss_attempt_coverage_evidence_model` in place of the header-only `pss_attempt_coverage_evidence` seed. The input accepts strings for `ccx_id`, `subsection_block_id`, `snapshot_id`, `coverage_start`, `coverage_end`, `verified_at` and `evidence_ref`. Each row must identify reconciliation of **all** applicable provider/native sources, actor links, eligibility decisions and refreshed facts for that class activity and period. Use explicit UTC bounds and verification time. An observed score, heartbeat or successful refresh alone cannot establish complete coverage. Withdraw a certificate when corrections or a new gap invalidate it. The model requires classified inventory, the matching publication and a reconciled current roster. Adjacent and overlapping evidence intervals combine. A hole leaves the result unknown.

To inspect a finite interval, compile the reconciliation analysis with the desired bounds and run its SQL under the authorized class scope.

```sh
dbt compile --select pss_attempt_period_reconciliation \
  --vars '{"pss_period_start_utc":"2026-11-02 10:00:00","pss_period_end_utc":"2026-11-02 11:00:00"}'
```

## Validation, handoff and rollback

- Prerequisites are the [class context and roster models](../context/README.md) and the [activity inventory](../core/README.md), including its Tutor source table and, for real classification, the approved Studio export and curriculum configuration. Load the approved rules/units and coverage evidence through the normal seed or configured model. Enabling xAPI identity and learning-event inputs in the target environment must follow the environment’s existing access controls.
- With the upstreams deployed, use `dbt build --select tag:pss_scores` to load the reviewed seeds, build the score models and run the focused checks. Rebuild the score view/target when `pss_current_score_rules` changes. Follow the dbt-clickhouse full-refresh procedure when the target schema or ordering changes.
- Install repository development requirements, run `dbt deps`, and run `python integration_tests/pss_scores/replay.py --tutor-pearson /path/to/deployment-plugin --tutor-aspects /path/to/analytics-plugin` with Docker. Supply the deployment plugin with the assignment type table DDL and the analytics plugin with the Aspects 3.0.3 migrations. The fixture writes only to its own ClickHouse database.
- The attempt and score tables and both restricted item evidence tables use replacement refreshes every four hours. Physical dependencies order the PSS attempts and native item evidence after `dim_course_blocks_mv`, the provider item evidence after `rpt_pss_activity_attempts_mv`, and the scores table after both attempts and structure. The public Quiz-item view reads the restricted provider result target. Course Licensing/MeasureUp current-state models and parsed xAPI use existing insert-driven pipelines. Source, structure and queue delays can extend end-to-end age beyond four hours. Inspect `system.view_refreshes` for recent successes, exceptions and actual dependency names in the deployed schema.
- In staging, reconcile sampled Quiz, Lab, Practice Exam and Final Exam records against source IDs and UTC timestamps at a common cutoff. Include a learner in two classes using the same product, repeat launches, backfills, conflicting version marks, reclassification and a deleted attempt. Compare the existing MeasureUp and Course Licensing reports. Record unmatched populations by diagnostic reason, two scheduled refreshes, source lag, representative-volume run time, memory and filtered query latency. Agree freshness and performance targets with Operations.
- The readiness models can join original MeasureUp attempt IDs to provider question/domain evidence for eligible practice. The public Quiz-item contract covers classified Quizzes. Class reporting must explicitly filter `is_participation = 1` for delivery and propagate unknown eligibility, use activity coverage for bounded zeros and keep all-time final coverage unknown without an independent source. Scope every dataset to authorized classes before computing totals.
- After staging acceptance and release approval, repeat scoped-access, source-count, version, freshness and performance checks in production. For rollback, withdraw dependent datasets, stop the score and attempt model refreshes, and restore the previously deployed package and policy configuration. Use downstream-first order when retiring targets or recreating them for a column/order change. Retain source events, current-state tables, and existing MeasureUp reports.
